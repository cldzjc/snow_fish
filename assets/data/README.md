# 地区数据（geo.json）

这里存放全国「省 → 市 → 区县 → 雪场」四级数据，注册、编辑资料、首页地区标签、
约约约的地区筛选都读这一份文件。

## 怎么改

结构如下，`cities` / `districts` / `resorts` 都可以为空数组：

```json
{
  "version": "20261125.1",
  "noFixedResort": "暂无固定雪场",
  "regions": [
    {
      "name": "河北",
      "cities": [
        {
          "name": "张家口",
          "districts": [
            { "name": "崇礼", "resorts": ["万龙", "富龙", "云顶"] }
          ]
        }
      ]
    }
  ]
}
```

- `name` 是显示名，也是存进数据库的字符串，改名会让老用户的地方显示成旧值。
- `noFixedResort` 会出现在雪场下拉的第一项，表示「没有固定雪场」。
- 改完不需要动代码，只要重新构建即可生效。

## 两种更新方式

| 方式 | 操作 | 是否需要重新编译 |
| --- | --- | --- |
| 内置 | 改 `assets/data/geo.json` → `flutter build web` | 需要 |
| 热更新 | 把同样的 `geo.json` 上传到站点根目录的 `data/geo.json` | **不需要**，刷新页面即可 |

启动时先读内置文件（保证首屏一定有数据），然后在后台请求站点的
`data/geo.json`，成功就用新文件覆盖。所以：

1. 平时改 `assets/data/geo.json`，随版本发布。
2. 临时补充雪场时，把改好的文件放到 `web/data/geo.json` 再部署，
   或者直接覆盖服务器上的 `data/geo.json`，用户刷新页面就能看到。

## 现有数据说明

当前是种子数据：31 个省级行政区的主要城市，以及已知雪场（崇礼各雪场、
北大湖、长白山、亚布力、可可托海、太子岭、南山、军都山等）。
尚未收录的雪场直接往对应区县的 `resorts` 里加即可。

# 圈子数据（circles.json）

**圈子不需要单独维护一份清单**：它由 `geo.json` 自动派生——

- 每个有雪场的区县 → 一个区县圈，例如 `河北·张家口·崇礼` → 「崇礼圈」；
- 每个雪场 → 一个雪场圈，例如 `河北·张家口·崇礼/富龙` → 「富龙圈」；
- 区县圈包含旗下所有雪场圈，所以崇礼圈能看到富龙、万龙的帖子。

所以**加雪场就是在 geo.json 里加一条**，圈子会自动出现。

`circles.json` 只用来做覆盖（改名 / 隐藏 / 置顶排序），留空就是完全按 geo.json 派生：

```json
{
  "hide": ["香港", "澳门"],
  "rename": { "崇礼": "崇礼雪区" },
  "order": ["河北·张家口·崇礼", "北京·北京·密云", "吉林·吉林·北大湖"]
}
```

| 字段 | 作用 |
| --- | --- |
| `hide` | 隐藏这些地区/雪场，可以写完整路径（`北京·北京·延庆`）或单个名字（`延庆`） |
| `rename` | 把显示名换掉，键是原名，值是显示名；只影响界面，不改数据库里的路径 |
| `order` | 圈子列表的优先顺序，按地区完整路径；没列到的排在后面 |

热更新方式和 geo.json 一样：把改好的 `circles.json` 放到站点根目录的
`data/circles.json`，刷新页面即可，不用重新编译。
